### 3. 时序能力动态更新（v4滑动窗口引擎）

22,884条JD → 按岗位+JD发布时间排序 → 滑动窗口采样 → 双阈值检测 → 三层过滤 → 5维变化分类。

**v4核心架构：**
- **滑动窗口**：窗口大小=10条JD，步长=3条，自适应小岗位（4-9条JD自动降为前后两半对比）
- **三策略并行**：累积对比(window[0] vs window[i]) + 间隔对比 + 首尾对比，确保渐变趋势检出
- **双阈值检测**：p<0.05 + h≥0.2（统计显著）OR h≥0.5（大效应量，小样本也能抓）

| 层级 | 方法 | 解决的问题 |
|------|------|-----------|
| 第1层 | Fisher精确检验(双尾) + Cohen's h效应量 | 排除采样噪声（双阈值：p<0.05+h≥0.2 OR h≥0.5） |
| 第2层 | Jaccard抄袭簇检测 + 通胀系数校准 | 排除技能通胀（相似度>0.8视为抄袭） |
| 第3层 | 过时技能知识库 + 软技能黑名单 | 排除已知旧技能和伪技能 |

**5维变化分类（增删改全覆盖）：**
| 类别 | 数量 | 说明 |
|------|------|------|
| 技能新增 | 847 | 窗口间从无到有 |
| AI技能新增 | 170 | 大模型/智能体等AI技能 |
| 技能衰退 | 1,045 | 技能需求显著下降 |
| 技能权重上升 | 991 | 出现率显著增长 |
| 技能权重下降 | 917 | 出现率显著降低 |
| 过时技能淘汰 | 2 | 已知过时技术标记 |
| 升级（加分→必备） | 13 | 技能重要性跃升 |
| 降级（必备→加分） | 22 | 技能重要性下降 |

**最终数据：760岗位 × 3~112个连续采样点 × 4,007个可信变化**（all高/中置信度，零低级噪声）

## 二、创新点

### 创新1：从"静态快照"到"动态演化感知"

传统岗位分析输出"当前需要什么技能"，本系统通过**CapabilityUpdater v4时序引擎**（JD排序滑动窗口 + 累积对比策略 + Fisher双尾精确检验 + Cohen's h效应量双阈值 + 抄袭簇通胀校准 + 过时知识库 + 5维增删改分类）七层处理，输出"技能要求在时间维度上的可信变化"，每个岗位生成3~112个连续采样点供前端渐变渲染。

v4关键升级：从v3日历季度窗口（仅2-4个粗粒度时间点）完全重写为JD计数滑动窗口（窗口大小=10条，步长=3条），实现平滑连续的趋势曲线。三策略并行（累积对比+间隔对比+首尾对比）确保相邻窗口70%重叠下仍能检出渐变信号。在全量22,884条JD、760个有效岗位上检测到4,007个可信变化（高置信度1,430项，中置信度2,577项），覆盖技能新增(847)、AI技能新增(170)、技能衰退(1,045)、权重上升(991)、权重下降(917)、升级(13)、降级(22)、过时淘汰(2)共8个维度。新增最小出现率阈值(5%)过滤低频噪声技能。

### 创新2：检测→矫正闭环

不同于常见做法（检测完写个报告就结束），本系统的**图谱校准器**将四类问题（通胀、时滞、噪声、幻觉）的检测结果直接转化为矫正动作：通胀感知降权计数、预测性技能激活时间线、Fisher检验自动过滤、白名单+RAG验证分类。最终输出的图谱每个节点都经过校准。

### 创新3：七项可量化指标的评估体系

每项指标对标比赛评分标准，有明确的Ground Truth和计算公式。每项可复现、可验证，解决传统系统"效果好但没有数字"的问题。

### 数据目录结构

```
小挑/
├── 【已标注】filtered/
│   └── jd_v2/                    ← 164个CSV，22,884条已标注JD（输入）
├── capability_updater.py         ← v4滑动窗口引擎（主程序）
├── graph_calibrator.py           ← 图谱校准器
├── annotate_jd_v2.py             ← JD标注主程序（可选，含动态更新写回）
├── capability_update_report.json ← 输出1：全量时序报告

└── calibrated_graph.json         ← 输出3：最终校准图谱
```

### 运行步骤

**第一步：能力动态更新检测**

```bash
cd 小挑/
python capability_updater.py \
    --annotated_dir "./【已标注】filtered/jd_v2/" \
    --output capability_update_report.json \
    --graph_output capability_graph_updates.json \
    --window_size 10 \
    --step 3
```

输出：
- `capability_update_report.json`（7.9MB）：760岗位×timeline×changes
- `capability_graph_updates.json`（4KB）：4,007条图谱更新

参数说明：
| 参数 | 默认值 | 含义 |
|------|--------|------|
| `--window_size` | 10 | 滑动窗口大小（条JD） |
| `--step` | 3 | 窗口滑动步长（条JD） |
| `--min_jd` | 2 | 单窗口最小JD数 |
| `--top_n` | 0 | 限制前N个岗位（0=全部） |

**第二步：图谱校准**

```bash
python graph_calibrator.py
```

自动读取 `capability_graph_updates.json`（优先）或 `capability_update_report.json`（回退），输出 `calibrated_graph.json`。

**第三步（可选）：标注数据回写**

```bash
python annotate_jd_v2.py \
    --output_dir "./【已标注】filtered/jd_v2/" \
    --enable_dynamic_update
```

读取预生成的 `capability_update_report.json`，将动态更新摘要写回每个CSV的"能力更新"字段。

### 核心算法说明

| 组件 | 方法 | 用途 |
|------|------|------|
| 滑动窗口 | 窗口大小=10条JD，步长=3条 | 生成3~112个连续采样点 |
| 自适应窗口 | 4-9条JD降为前后两半对比 | 小岗位也能参与分析 |
| 累积对比 | window[0] vs window[i] | 检测渐变趋势（避免70%重叠致盲） |
| Fisher精确检验 | 双尾，p<0.05 | 排除采样噪声 |
| Cohen's h | h≥0.2（统计）或 h≥0.5（大效应） | 双阈值，小样本不丢 |
| Jaccard聚类 | 相似度>0.8视为抄袭簇 | JD权重=1/簇大小 |
| 最小出现率 | 5% | 过滤低频噪声技能 |
