## 0. 数据清洗（前置步骤）

标注前必须剔除非「新一代信息技术」行业的JD。

### 0.1 文件级整类剔除（无救回路径）
以下岗位类别**整体**不属于新一代信息技术，直接删除全文件：
- `智能硬件装调员` — 硬件安装/调试技工
- `物联网安装调试员` — 设备安装工
- `云网智能运维员` — JD实际为风电/光伏/地铁设备维护，非云计算IT

### 0.2 行级剔除（需二次校验）
- 光伏/储能/风电/太阳能/电池（无IT关键词时）
- 传统制造（流水线、装配工、操作工、焊工、车工、CNC、注塑）
- 物流/运输（司机、货运、配送、快递员）
- 建筑/土木（工程造价、施工员、监理）
- 金融销售（保险销售、理财顾问、贷款专员）
- 传统零售/餐饮/美容/物业/安保/农业/矿产
- 纯客服/呼叫中心、纯行政/文员/前台/会计/HR/法务
- 非数字营销（市场推广/品牌策划，不含技术/数据/数字关键词）
- 岗位名匹配装调/装配/安装调试等技工模式（JD有IT信号时救回）

### 0.3 必须保留
- 命名包含IT关键词的岗位（工程师、架构师、程序员、算法、AI、数据等）
- JD文本中包含≥1个信息技术强信号的岗位
- 硬件类：嵌入式、单片机、FPGA、芯片、驱动开发、BSP、ARM、RTOS、Verilog、VHDL
- 通信类：5G、LTE、射频、天线、光通信、核心网、SDN、NFV
- IoT/数字孪生/区块链

### 0.4 无技能JD剔除（后置步骤）

标注完成后，每条JD必须有至少1个字典可提取的技术技能。字典完全抽不到技能的低质量JD直接剔除：

| 剔除原因 | 判定 |
|---------|------|
| JD过短 | `len(skill_requirements) < 60` |
| 非技术岗位 | 岗位名含：销售、客服、讲师、培训、运营、推广、营销 |
| 纯职责描述 | 有岗位名但JD无具体技术名词 |
| 产品岗无技能 | 产品经理/专员 但JD纯职责描述无具体工具/方法 |

**实现**: `filter_no_skill_jds.py`，输出至 `【已标注】filtered/`

**效果**：49,210 → 36,938条（剔除12,272，24.9%）

## 1. 技能通胀

**判定说明：** 判断JD是否堆砌AI技术名词，区分岗位正常完整技术栈与无意义重复、超岗位要求的罗列。

**特别注意：**
- 初级岗 AI 技能 ≥3 轻度、≥5 中度、≥8 且大量重复为重度
- 中高级岗位同步上调阈值（中级：4/7/12，高级：6/10/15）
- 岗位层级匹配的完整技术栈不判定通胀
- 仅同类同义词重复（如同一同义词组命中≥3个）、技能和业务无关、要求明显超出岗位层级才认定通胀

**同义词组：**
| 组 | 词项 |
|---|------|
| 大模型组 | 大模型、LLM、大语言模型、GPT、ChatGPT、DeepSeek |
| AIGC组 | AIGC、生成式AI、GenAI、AI绘画、AI写作 |
| Agent组 | Agent、AI Agent、智能体、Multi-Agent、多智能体 |
| 图像生成组 | Stable Diffusion、SDXL、Midjourney、Sora、文生图、文生视频 |
| RAG组 | RAG、检索增强生成、Graph RAG |
| 微调组 | LoRA、QLoRA、PEFT、微调、大模型微调、SFT、RLHF |

**输出格式：** `无` / `轻度` / `中度` / `重度`

## 3. 必备技能（限制1-6项）

**判定说明：** 岗位履职硬性底线、简历初筛标准。区分 AI新兴技能、传统技术 两大类别。

**特别注意：**
- 沟通、抗压、协作等素质类软技能**禁止**作为必备技能
- 需求分析、Axure、PRD、项目管理等专业方法论/工具属于硬技能，可纳入必备
- JD存在多条硬性技能需完整提取，漏提取属于标注错误
- **AI岗位的标注不能倾向于只提取AI新兴技能，遗漏Python/SQL等传统硬性编程要求**

**软技能黑名单（不入必备）：**
沟通能力、沟通协调、表达、团队合作、团队协作、团队管理、领导力、管理能力、学习能力、自驱力、责任心、抗压能力、运营（产品运营/用户运营等）、用户体验/UX、商务谈判、客户关系、销售、市场营销、创新思维、逻辑思维、分析能力、英语、文字功底、细心、耐心

**硬性专业技能（可入必备）：**
需求分析、项目管理、PRD、MRD、技术文档、Axure、Figma、Sketch、Adobe XD、Photoshop、Illustrator、产品设计、原型设计、JIRA、Confluence、Scrum、敏捷开发、Git、SVN

**必备为空处理：**
- 当JD全部使用"优先/加分"语气时，所有技能归入加分
- 必备为空时：从加分中全量提升（AI新兴技能优先，最多6个），剩余仍留加分（最多4个）
- 提升的技能标注"（注：以下技能从加分项推断，JD未明确列为硬性要求）"

**输出格式：** 每条 `【技能名｜类别｜掌握级别】`，多条用 `；` 分隔
- 类别：`AI新兴技能` / `传统技术`
- 掌握级别：`精通` / `熟练` / `熟悉` / `了解`

**掌握级别判定规则：**
| 级别 | 上下文关键词 |
|------|------------|
| 精通 | 精通、深入理解、专家、资深、深度、多年、扎实+经验 |
| 熟练 | 熟练、掌握、独立完成/开发/负责/设计 |
| 熟悉 | 熟悉、具备、有经验、相关经验、理解原理 |
| 了解 | 了解、知晓、知道、接触过、愿意学习、感兴趣、关注 |

## 4. 加分技能（限制0-4项）

**判定说明：** 择优录用参考条件，不属于入职硬性门槛。

**特别注意：**
- **禁止**预设"AI新兴岗位RAG/Agent大多归入加分"的规则——视JD具体语境决定
- JD标注优先、加分、有XX经验更佳的内容**必须全部提取**
- 含具体技术名词的不能漏提取（如"有Python开发经验更佳"→Python不能漏；"有实际使用主流大模型解决问题的经验...加分"→大模型不能漏）
- JD无加分描述可填0；存在加分项未提取判定为标注错误

**加分信号识别：**
- 关键词：优先、加分、者优先、更佳、尤佳、优先考虑、加分项
- 排除非技能加分：博士优先、硕士优先、985/211优先、本地优先等

**输出格式：** 同必备技能：`【技能名｜类别｜掌握级别】`

## 5. 是否新岗位候选

**判定说明：** 两项条件**同时满足**，才可判定为"是"：
- ① 岗位核心工作、核心产出依托 LLM/AIGC/RAG/Agent/多模态大模型，AI为岗位主业（≥50%），非辅助工具
- ② 企业长期稳定招聘AI业务，非短期概念虚岗

**特别注意：**
- 岗位名称含 `AI`、`大模型`、`LLM`、`Agent`、`AIGC`、`智能体` → 优先进入校验流程，放宽条件②门槛
- AI相关核心职责占比 ≥50% 视为AI主业
- **仅加分项提及AI判定为否**（岗位名含核心AI词的除外——岗位名已说明核心工作）
- 深度学习、机器学习、NLP、CV等传统AI技术**不触发**新岗位判定；仅LLM/AIGC/RAG/Agent/多模态大模型触发

**判定逻辑：**
```
条件①（满足任一）：
  a. 岗位名含大模型/AIGC/Agent/LLM/智能体
  b. 岗位名含算法/AI + ≥2个不同新兴AI信号
  c. AI信号在必备语境中 + 句子级AI占比≥30%
  d. ≥4个不同新兴AI信号

条件②（岗位名含核心AI时≥1分，其他≥2分）：
  - JD包含职责描述（+1）
  - JD包含任职要求（+1）
  - JD长度≥60字（+1）

条件① ∧ 条件② → 是
```

**输出格式：** `是` / `否`

## 6. 能力更新

**判定说明：** 横向对标行业内同类型常规岗位，识别本岗位技能需求出现的调整变化。

**特别注意：**
- 填写**禁止笼统表述**（如"新增AI技能"），必须写明具体技能名称
- 传统岗位已新增AI技能要求（Agent/RAG/大模型出现在必备技能中）→ 标注"新增"+具体技能名
- 近义词、大小写不同但所指相同 → 记为同一个词语
- 传统岗位关键词匹配范围：产品经理、前端、后端、测试、运维、爬虫、Java、Python、C++、Android、iOS、嵌入式、项目经理、数据分析、硬件、网络、通信、运营、设计、销售、客服、技术支持、实施、架构师、DBA、系统管理员、安全、质量、电子、电气、自动化、机械、结构

**输出格式：** `无` / `新增`；若为"新增"，补充写明具体变更的技能名称。如：`新增AI技能要求（大模型、RAG、Agent）`

## 7. 五级抽取管线（必备为空兜底）

字典匹配覆盖约83%的JD。对于字典抽不到的JD（口语化表述、纯职责描述、极简JD），构建五级管线逐级兜底：

```
JD原文
  │
  ├─ 第1级：字典精确匹配（400+技能词）
  │    命中 → 直接输出，source=extracted，confidence=0.85
  │    未命中 → 进入第2级
  │
  ├─ 第2级：语义推断（fuzzy规则 + 岗位名→默认技术栈）
  │    "使用AI工具完成文案生成" → AIGC
  │    "模型开发" → Python, PyTorch, 模型训练, 模型部署
  │    "计算机视觉" → Python, OpenCV
  │    "推动产品落地、设计路线图" → 产品设计, 需求分析, 项目管理
  │    "分析追踪数据指标" → 数据分析
  │    命中 → RAG验证（技能库+JD原句双锚定）
  │
  ├─ 第3级：极简JD识别
  │    JD<60字且无岗位名 → 直接跳过，标记invalid_skip
  │
  ├─ 第4级：职责→技能隐式推断
  │    "制定推广策略" → 市场营销
  │    "带领团队完成业绩" → 团队管理
  │    "协调跨部门资源" → 跨部门协作
  │    "撰写维护技术文档SOP" → 技术文档
  │    命中 → RAG验证 → source=inferred_duty，confidence=0.5
  │
  └─ 第5级：同类岗位协同过滤
       查全量标注数据中同名岗位的高频必备技能Top5
       命中 → RAG验证 → source=collaborative_filter，confidence=0.35
       推入人工审核队列
```

### 各级入库标记

| 级别 | source | confidence | 说明 |
|------|--------|------------|------|
| Tier 1 | extracted | 0.85 | 字典直接命中，高置信度 |
| Tier 2 | inferred_llm | 0.6 | 语义推断，经RAG验证 |
| Tier 4 | inferred_duty | 0.5 | 职责→技能映射，隐式推断 |
| Tier 5 | collaborative_filter | 0.35 | 同类岗位协同过滤，低置信度，需人工确认 |

## 8. 幻觉防控

### 四层白名单 + RAG三源验证

```
NER/LLM输出的技能
  │
  ├─ 第1关：软技能黑名单 → rejected（40项，确定性规则）
  ├─ 第2关：过时技能字典 → outdated（25项，确定性规则）
  ├─ 第3关：描述性短语模式 → rejected（4类正则，确定性规则）
  ├─ 第4关：LLM约束输出 → 禁止生成NER未提取的技能
  │
  └─ 第5关：RAG三源验证 ← 只在需要外部知识时调用
        ├─ 技术知识库（本地技能库）
        ├─ JD时序数据库（历史上是否出现过）
        └─ 趋势信号（GitHub/arXiv先行指标）
        ↓
        ├─ 双锚定（技能库+JD原文） → verified
        ├─ 三源全空+LLM模式 → hallucinated
        └─ 中间态 → needs_review → 人工审核队列
```

**关键原则：** 前四关是确定性规则——不需要RAG，字典+正则已经做到100%精确。RAG只在第五关有价值：当白名单不认识一个技能时，去外部世界确认它到底是新技术还是幻觉。

## 10. 全文通用规则

- JD中若出现同义词、近义词或大小写字母且所指相同的，在性质相同的前提下，记为同个词语

- 编码格式：UTF-8 BOM (`utf-8-sig`)
- 输出CSV保留原始所有列，另增7列标注字段
